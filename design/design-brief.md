# Design Brief｜客服知識中心版型規範

- 版本：1.0.0
- 對應 token：`design/tokens.json` v1.0.0
- 狀態：**凍結契約**。本檔一經凍結，AI 在日常維護知識頁時不得自行更動；要改版型必須由人類先修訂本檔並升版號，再調整 `assets/style.css` 與 `templates/`。

本檔是版型的唯一真實來源。每條規則標記執行方式：

| 標記 | 意義 |
| --- | --- |
| `[GATE]` | 驗證器 `scripts/validate.py` 會擋，違反即無法交付 |
| `[REVIEW]` | 機器無法完全判定，交由人工審查 |

---

## 1. 設計哲學

客服知識頁的首要任務是讓焦慮中的使用者在最短時間找到答案。因此版型的優先順序是：**可掃描 > 可讀 > 美觀**。

1. 每一頁都要能在三秒內回答「我在哪裡、我要找的答案在不在這頁」。
2. 不使用輪播、不使用進場動畫、不使用需要滑鼠停留才出現的關鍵資訊。
3. 沒有 JavaScript 也要能讀完全部內容，搜尋與深色模式切換屬於漸進增強。

## 2. 版面骨架

### 2.1 全站共用

`[GATE]` 每一個產出頁面都必須依序具備下列結構節點：

1. `.skip-link`：跳至主要內容的鍵盤捷徑，聚焦前隱藏、聚焦後可見。
2. `header.site-header`：品牌標誌連回知識中心首頁，右側為主題切換按鈕。
3. `main#main`：主要內容區，必須帶 `id="main"` 供 skip link 對應。
4. `footer.site-footer`：包含最後建置時間與知識庫版本。

`[GATE]` 每頁 `<head>` 必須有唯一的 `<title>`、`<meta name="description">`、`<link rel="canonical">`。

### 2.2 容器與間距

- 內容容器最大寬度 `var(--layout-container)`，兩側內距 `var(--space-5)`。
- 內文段落行寬上限 `var(--layout-measure)`，避免長行影響閱讀。
- 垂直節奏一律取自 `--space-*` 刻度，不得出現刻度以外的魔術數字。

## 3. 四種頁型

### 3.1 首頁（知識中心）

由上而下：頁面標題區（H1 加一句話說明）、搜尋列、分類卡片格線、熱門問題清單、聯絡客服區塊。

- 分類卡片格線：桌機三欄、平板兩欄、手機單欄。
- `[GATE]` 首頁必須出現搜尋列 `#kb-search` 與聯絡客服區塊 `.contact-cta`。

### 3.2 分類頁

麵包屑、分類標題與說明、該分類知識卡清單（依 `weight` 由小到大、其次依更新日期由新到舊）、聯絡客服區塊。

### 3.3 知識卡內頁

`[GATE]` 依序必須具備：

1. `nav.breadcrumb`：知識中心 > 分類 > 本篇。
2. `h1.article-title`：即 frontmatter 的 `title`。
3. `.article-meta`：更新日期、負責窗口、狀態標籤。
4. `.answer-summary`：一段話直球回答，位於正文之前。
5. `article.article-body`：正文。
6. `.related`：相關問題，至少一則。
7. `.contact-cta`：仍未解決時的聯絡管道。

### 3.4 404 頁

提供搜尋列與回首頁連結，不得只顯示錯誤碼。

## 4. 元件規格

### 4.1 知識卡（清單中的一則）

- 結構：問題標題（連結）、一句話答案摘要、分類標籤、更新日期。
- 整張卡片可點擊，但標題本身必須是真正的 `<a>`，確保鍵盤與螢幕閱讀器可用。
- Hover 與 focus 時提升 `--shadow-card` 至 `--shadow-raised`，位移不超過 2px。

### 4.2 狀態標籤 `.badge`

| 狀態 | 用色 token | 顯示文字 |
| --- | --- | --- |
| `published` | `--color-accent` | 已發布 |
| `review` | `--color-warn` | 審核中 |
| `deprecated` | `--color-danger` | 已停用 |

`[GATE]` `status: deprecated` 的知識卡不得出現在首頁熱門問題與分類頁清單，僅保留內頁並顯示停用提示。

### 4.3 搜尋

- 純前端搜尋，讀取建置時產出的 `search-index.json`。
- 無結果時顯示「找不到相符的問題」與聯絡客服連結，不得留白。
- `[REVIEW]` 搜尋輸入框必須有可見標籤或 `aria-label`。

### 4.4 聯絡客服區塊 `.contact-cta`

固定三個資訊：線上客服時間、客服信箱、常見問題回報連結。文案由 `content/taxonomy.yml` 的 `site.contact` 提供，不得寫死在樣板。

## 5. 色彩與主題

- `[GATE]` `assets/style.css` 內除了 `:root` token 宣告區塊外，不得出現任何 `#RRGGBB` 或 `rgb()` 字面值，一律使用 `var(--color-*)`。
- 支援三態主題：跟隨系統、強制淺色、強制深色，以 `data-theme` 屬性切換。
- `[REVIEW]` 內文與背景對比需達 WCAG AA（4.5:1），大標題至少 3:1。

## 6. 字體與文字

- 字級只能取自 `--size-*` 刻度。
- H1 使用 `--size-3xl`，H2 `--size-xl`，H3 `--size-lg`，內文 `--size-md`。
- `[GATE]` 中文內容一律使用全形標點，且全站禁用破折號（—、––、--）。理由是破折號在客服語境容易造成斷句誤讀，且中英標點混用會破壞字距。

## 7. 響應式

| 斷點 | 行為 |
| --- | --- |
| `< 480px` | 單欄，卡片格線收成一欄，麵包屑允許橫向捲動 |
| `480px 至 1024px` | 分類卡兩欄 |
| `> 1024px` | 分類卡三欄，內頁維持單欄置中 |

`[GATE]` 任何情況下不得出現橫向捲軸，寬元素（表格、程式碼區塊）自行以 `overflow-x: auto` 內捲。

## 8. 無障礙

- `[GATE]` 每頁只有一個 `<h1>`。
- 標題階層不得跳級，`h2` 之後才可出現 `h3`。
- 所有可互動元素需有可見的 `:focus-visible` 外框，寬度 2px，顏色 `--color-brand`。
- `[REVIEW]` 圖片一律提供 `alt`，裝飾性圖片給空字串。

## 9. 列印

- 列印時隱藏頁首導覽、主題切換、搜尋列與聯絡客服區塊。
- 內頁列印需保留標題、更新日期與正文，並在頁尾附上該頁網址。

## 10. 效能

- `[GATE]` 不得引用任何外部 CDN 的 JavaScript 或 CSS，全部資源同源自帶。
- 單頁 HTML 未壓縮大小建議在 80KB 以內。`[REVIEW]`
